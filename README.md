# Магазин косметики

Flutter Web, практические работы 2–4. Сейчас приложение работает с REST API
магазина косметики через Dio. Отдельная база данных для ПР4 не требуется.

## Запуск

Два терминала из папки проекта:

```bash
# Терминал 1: API
./scripts/start-api.sh
# Эквивалент при установленном Node.js:
# node api/mock-server.js --port 8080 --origin http://localhost:5555
```

```bash
# Терминал 2: Flutter
flutter pub get
./scripts/start-web.sh
# Без автоматического открытия Chrome:
# flutter run -d web-server --web-hostname localhost --web-port 5555 --dart-define=API_BASE_URL=http://localhost:8080/api
```

Открыть **http://localhost:5555/products**. Проверка API:
http://localhost:8080/api/__health. Не заменять localhost на 127.0.0.1:
для CORS это разные источники. Если порт 5555 уже занят предыдущим запуском,
остановить прежний веб-сервер перед запуском Flutter.

Скрипт API использует системный Node.js либо локальный runtime в `.tools/`
(он не включается в Git). На другом компьютере достаточно Node.js 18+.
Изменения сохраняются при обновлении страницы, пока сервер работает.
**Перезапуск API возвращает исходный учебный каталог.** Данные ПР3 в localStorage
не удаляются, но текущая версия их не читает и не переносит автоматически на сервер.

## Практика 4

- Полный CRUD всех пяти сущностей через HTTP. В обычном запуске нет локального
  резервного каталога. Интерфейс `CatalogRepository` сохранён.
- `API_BASE_URL` задаётся через `--dart-define`; connectTimeout 10 с,
  receiveTimeout 15 с; debug-интерсептор пишет метод, URL и статус без тела запроса.
- Ошибки преобразуются в собственные исключения; 422 показывается под полями,
  409 — понятным сообщением. Виджеты не импортируют Dio.
- Поиск/фильтры/сортировка/пагинация на сервере, клиент хранит текущую страницу.
- Устаревший запрос списка отменяется CancelToken. До трёх попыток чтения при
  сетевом сбое с паузами 300/600 мс; записи и HTTP-ошибки не повторяются.
- Бренды, категории, поставщики кэшируются для форм; товары и покупатели
  не скачиваются целиком. После изменений кэш обновляется.
- Сохранение блокирует кнопку до завершения, повтор не создаёт дубликат.

Сценарии: `/products?__delay=1500`, `/products?__fail=500`,
`/products?search=несуществующийтовар`. Для настоящей ошибки соединения
остановить API, обновить список, запустить API и нажать «Повторить».

[Контракт API](api/КОНТРАКТ-API.md) · [Материалы ПР4](docs/practice4.md).

## Практика 3

Пять разделов: **товары, бренды, категории, поставщики, покупатели**.
У покупателя есть вложенная карта лояльности. Во всех разделах доступны список,
карточка, создание (кнопка «+» у заголовка), редактирование, логическое и физическое
удаление, восстановление, поиск, фильтр, сортировка, выделение и пагинация 10/25/50.

- У товара один бренд и один поставщик (многие к одному), несколько категорий
  (многие ко многим). У поставщика выбираются поставляемые бренды.
- После выбора поставщика в форме товара доступны только его бренды. Несовместимый
  ранее выбранный бренд сбрасывается. Связи также проверяются в репозитории.
- У покупателя ровно одна карта лояльности, редактируемая в той же форме.
- Общая форма `EntityFormScreen` строится из `FieldSpec`: пять сущностей используют
  одинаковые разметку, отправку и показ ошибок. Создание/изменение — один экран.
- Ошибки обязательности, длины, чисел, цены, почты, телефона, дат и выбора связей
  выводятся под полями. Цена хранится целым количеством копеек.
- Уникальны артикул товара, почта покупателя и номер карты (без учёта регистра,
  с исключением самой редактируемой записи). Удалённые записи тоже резервируют значения.
- Удаление используемого поставщика, бренда или категории запрещено с показом
  числа зависимых записей. Групповое удаление проверяется целиком до изменения.
- `PopScope` и `go_router.onExit` защищают несохранённые изменения при навигации.
  На web `beforeunload` дополнительно просит браузер предупредить о закрытии/обновлении
  вкладки; вид и показ этого системного диалога определяются браузером.
- В реализации ПР3 (сейчас только в тестах) `shared_preferences` сохраняет JSON в localStorage после каждой успешной операции.
  Используется ключ `cosmetics_shop_v2`, версия 2. Старые/повреждённые данные
  сохраняются в резервной копии; пользователь видит сообщение о восстановлении.
- Изменения в памяти подтверждаются только после успешной записи. Сохранения в
  одной вкладке выполняются последовательно. Данные сохраняются для конкретного
  адреса и порта; живой обмен изменениями между одновременно открытыми вкладками
  не реализован. В ПР4 рабочее приложение переведено на REST API.

Бренды реальные: Bioderma, Garnier, COSRX, Maybelline New York, NIVEA,
L’Oréal Paris, CeraVe, La Roche-Posay. Ассортимент и цены демонстрационные;
поставщики и покупатели вымышлены. При первом запуске: 30 товаров, 8 брендов,
5 категорий, 3 поставщика, 12 покупателей с картами.

## Практика 2 сохранена

Provider / ChangeNotifier, `EntityTable<T>`, адаптивные карточки при ширине <600 px,
параметры списка в адресе, история браузера и задержка поиска 350 мс. Изменение
условий сбрасывает страницу и выделение. После удаления последней записи номер
страницы корректируется; устаревший результат не отменяет новую навигацию.

Для демонстрации ошибки загрузки: меню «Проверка состояний» → «Показать пример
ошибки» → «Повторить». Поиск `несуществующийтовар` показывает пустой результат.

Ошибка `deleteMany` из задания: выражение `b[i].isDeleted` обращалось к одной
сущности как к массиву, причём индекс ещё вычислялся. Правильно: `b.isDeleted`.


переходы, пагинацию и мобильную вёрстку.
